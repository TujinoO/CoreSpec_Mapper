# CoreSpec Mapper V5.2 实施与验证报告

日期：2026-07-21
验证项目：NC-1，5,446 × 320 × 212 SWIR

## 结论

V5.2 已建立“通用自适应引擎”和“项目验证配方”两条明确隔离的路线。NC-1 使用已批准人工掩膜与冻结 V3 配方完成全景复跑，平衡/敏感两档共 14 个矿物比较全部与历史流程逐像元一致，质量 A，`publishable=true`。

历史分类结果仅作为流程弱标签。它证明预处理、参考谱、阈值、分类和空间清理能够稳定回归，不等同于独立 XRD、拉曼、薄片或点光谱真值。

## 发布基线

| 项目 | V5.2 状态 |
|---|---|
| 应用与桌面版本 | 5.2.0 |
| 通用执行引擎 | `adaptive_v5`，用于新项目无标签证据探索 |
| 项目验证引擎 | `validated_v3`，用于冻结历史流程回归 |
| 桌面流程 | 八步：项目、数据、掩膜、矿物、模式、阈值试算、运行、结果 |
| 掩膜生产门 | 覆盖率、内部填充率、组件/轮廓风险与人工批准 |
| NC-1 发布状态 | A，`publishable=true`，14/14 项逐像元回归通过 |
| 自动化测试 | 110 passed |

双引擎必须按项目目的选择：有可靠历史人工基准的 NC-1 使用冻结配方；新项目才使用 Catalog 有界的自适应阈值。两者输出可以比较，但参数来源不能静默混用。

## 关键修复

1. 新增 `v5-validate` 回归门，输出逐矿物 IoU、Precision、Recall、面积差和失败原因。
2. 新增 `validated_v3` 项目配方引擎；NC-1 平衡/敏感配置、人工掩膜和历史结果均被显式记录。
3. 新增 GeoCore M1-2 适配器：检查滑窗推理代码、模型注册、Manifest 与权重，模型齐备后可直接调用并适配到 SWIR 网格。
4. 新增自动掩膜内部填充率与最小覆盖率门。托盘轮廓、裂缝网络或严重漏提不再仅凭总面积通过。
5. 新增掩膜人工批准门，运行服务和桌面端均会阻止未批准掩膜进入分类。
6. 新增孤立 ENVI 头文件识别；可选 NIR 缺失数据体时记录结构化警告，不中断有效 SWIR 项目。
7. 桌面端改为八步状态化流程：项目、数据、掩膜、矿物、模式、阈值试算、运行、结果。
8. 桌面端新增执行引擎选择、阈值 JSON 导出、非递增 ETA、结构化告警、结果 50%/1:1/200% 缩放和滚动平移。
9. 非发布级结果不再显示为无条件绿色完成。
10. 新增逐组拒绝瀑布，分离候选、光谱/深度/分类证据拒绝、空间清理和最终分类数量。

## 自动掩膜验证

V5.1 错误自动掩膜相对人工掩膜的 IoU 为 0.1471，召回为 18.24%。V5.2 对原始 SWIR 的光谱回退结果为 56,023 像元、覆盖率 3.2147%、相对人工掩膜召回 16.06%，低于默认 5% 覆盖门，因此被阻断。

GeoCore M1-2 当前交付目录缺少：

- `geocore_mask/models/registry.py`
- `models/core_mask_unet_v1/model_manifest.json`
- Manifest 所指向的模型权重

V5.2 已完成调用适配与状态检查，但在模型包补齐前，NC-1 生产路线继续使用已批准同网格人工掩膜。系统不会静默声称模型推理成功。

掩膜进入分类前还必须通过人工批准门。批准记录包括审核人、审核时间和备注；自动生成成功但未批准的掩膜不能直接启动矿物运行。

## 后续数据要求

通用自适应引擎仍需要跨钻孔独立真值验证。建议按矿物与深度段补充 XRD、拉曼、薄片或点光谱标签，并用盲测钻孔确定阈值外推能力。GeoCore M1-2 必须补齐正式模型包与 RGB→SWIR 配准参数，才能解除“人工掩膜优先”的生产约束。
